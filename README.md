# We Zaap

We Zaap is a mock interview app built for a University of North Texas hackathon, where it won an award. It generates role-based questions, supports voice answers, and returns feedback on each response.

## How it works

1. A Flask app serves the interview pages and handles registration, login, and sessions.
2. SQLAlchemy stores user records in PostgreSQL.
3. OpenAI generates interview questions from the selected role, difficulty, and company. The app can use built-in questions if question generation fails.
4. The voice flow uses gTTS for spoken prompts and OpenAI Whisper for transcription.
5. For answer feedback, the app selects context from a small role-specific knowledge base using **keyword matching**, then asks an OpenAI model to score and explain the answer. This is a simple retrieval-augmented feedback flow, not vector or hybrid search.

The knowledge base is assembled from a fixed list of public resources when the app starts. Availability and page content of those resources can affect startup and feedback.

## Stack

Python, Flask, SQLAlchemy, PostgreSQL, OpenAI API/Whisper, gTTS, Beautiful Soup, and HTML templates.

## Run locally

You need Python 3, PostgreSQL, and an OpenAI API key. FFmpeg may be needed for the audio conversion flow.

```bash
python -m venv .venv
# Activate .venv for your shell.
pip install -r requirements.txt
cp .env.example .env
```

Create a PostgreSQL database, then edit `.env` with your database URL, a long random `SECRET_KEY`, and your own `OPENAI_API_KEY`. Never commit `.env` or paste credentials into an issue.

```bash
python app.py
```

Open <http://127.0.0.1:5000>. The app creates its database tables at startup.

## Results and evaluation

**Result:** We Zaap won a UNT hackathon. The repository does not contain a repeatable benchmark, human-rated answer set, or measured model accuracy. The 0–100 feedback score is generated by the model for an individual answer; it is not a validated evaluation metric.

## Current limits

- Retrieval is keyword based over a small fixed resource list; it does not use embeddings or a vector database.
- Company-specific question guidance is a configured prompt, not a company-specific document corpus.
- Model feedback and scores should be reviewed by a person before being used for consequential decisions.
- This is a hackathon prototype. It needs security, reliability, and evaluation work before production use.
